Data provenance and reproduction

Manuscript data description

We analyzed public electric vehicle charging sessions in Edinburgh and Glasgow in January and July 2023 and 2024. The analysis used the session tables and connector inventory released with GridCharge (Batic, DOI 10.57967/hf/6647), whose upstream source is the ChargePlace Scotland (CPS) monthly performance archive. We used the recorded energy delivered per session and linked records to the inventory by charge point and connector identifiers. The AC sample used connectors with a snapshot rating of at most 22 kW. Each modeled geographic site groups connectors within a city that share an address after normalization and coordinates rounded to six decimal places. Both years use the same frozen inventory and site definitions. The actual electrical connection and contemporaneous connector ratings were unavailable. The geographic grouping and inventory ratings define the model's site and power proxies.

Session start times were interpreted in Europe/London civil time and converted to UTC. The January source records begin near 00:00 local time, and the July records span approximately 01:00 local time on the first day through 01:00 on the first day of the next month, consistent with UK daylight saving and UTC reporting boundaries. We set the modeled session end to the recorded start plus the recorded duration. The CPS public tables omit separate connection, unplug and power trajectory measurements. The resulting window is a transaction-based proxy for when the vehicle is available for charging. The model treats recorded energy delivery as the service requirement and applies the specified checkpoint constraints within this window.

We checked every session in the frozen site-week panels against the operator's original workbooks. All 6,462 records matched the source on device, connector, local start time, duration to the second and delivered energy to the precision retained in the input. All devices represented in the panels appeared in the associated operator point reports. Among devices observed in the same season in both years, all 23 January devices and all 25 July devices retained the same communication identifier, local authority and postcode. These comparisons support continuity of the observed device identifiers and geographic assignment. The reports list activity and location details, with charger categories in 2024. Connector-level power histories and electrical topology remain unobserved.

The common exogenous signals were the 30-minute Great Britain average electricity carbon intensity estimated from metered generation (the NESO API's actual field) and Elexon's APXMIDP short-term wholesale price index. Model costs and operational grid-import carbon footprints use these two signals. The 2023 anchor used JRC PVGIS 5.3 ERA5 PV estimates for a south-facing array tilted 35 degrees with 14% system losses. The same-method cross-year comparison used ERA5 global tilted irradiance from Open-Meteo for both years, with the same tilt and orientation and a fixed system efficiency of 0.86. We set normalized power to 0.86 times the reported irradiance in W/m2 divided by 1,000. The irradiance value describes the preceding hour. We shifted hour-ending timestamps back one hour and used the hourly value in both half-hours to preserve energy. The 2023 same-method dataset preserves its original charging records, carbon and price columns and timestamps.

Panel and reproduction workflow

1. Run the following command from the storage_value_study directory to retrieve missing snapshots and verify all the cached files. The script reads the three frozen manifests listed below. SHA-256 and byte count must match before a downloaded file is saved under its study filename.

   python submission_jte/fetch_snapshots.py

   data/raw_manifest.json
   cross_year_2024/data/raw_manifest.json
   cross_year_2024/data_harmonized_2023/raw_manifest.json

   Add --verify-only to run the check offline. The original operator workbooks are independent audit sources. The three manifests specify the files needed to recreate the model inputs. Live APIs can revise historical values or return different response metadata. In particular, Open-Meteo includes generationtime_ms. Exact byte-level reproduction therefore uses the preserved API response files when the live response differs. A checksum mismatch requires the frozen snapshot identified in the manifest.

2. Prepare the model input tables using the existing data scripts.

   python prepare_study_data.py --offline
   python cross_year_2024/prepare_holdout_data.py --offline
   python cross_year_2024/prepare_holdout_data.py --harmonize-2023 --offline

   The prepared metadata record row counts and sequential exclusions. The filters exclude invalid values, physically inconsistent energy at the modeled power ceiling, duplicate or overlapping records on a connector, and records outside the complete UTC window. The 2023 signal windows start 1 January and 1 July UTC and end before 26 January and 31 July, respectively, due to gaps in the carbon and price series. The 2024 signal inputs contain the full January and July UTC months. Analyses use complete Monday-through-Sunday UTC weeks and sessions contained within each week. The primary cross-year panel matches the same geographic site, calendar month and ordinal complete UTC week. Match and selection rules are recorded in cross_year_2024/protocol.json and submission_jte/service_protocol.json.

3. Follow submission_jte/REPRODUCE.txt to reconstruct the study inputs and rerun the service and controller analyses. The service runner verifies the checksums of the two frozen upstream panel result manifests and the service protocol.
